# 正文输出格式

新生成的正文使用下列模型可见协议：

```text
<content player="菜月昴">
  <story volume="01"></story>
  <time period="下午" layer="主线" basis="编辑演算">魔女历1000年01月01日</time>
  <now_plot>
旁白自然段。

{人物}「人物对白」

{#}「玩家对白」

<scene location="王都" time="下午" mood="不安">转场文本。</scene>

<ability user="贝亚特丽丝" name="阴魔法" kind="魔法" affinity="阴">
  <effect>发动过程与实际结果。</effect>
  <description>一至三句能力介绍。</description>
</ability>

<check type="闪避" actor="菜月昴" target="艾尔莎">1d20=14｜情境+2｜DC15｜成功｜后果</check>

<restart deathId="loop-001" checkpoint="赃物库前">世界重启叙述。</restart>
  </now_plot>
</content>
<UpdateVariable>...</UpdateVariable>
```

## 根结构

- 规范根语法为 `响应 ::= content [UpdateVariable]`，`content ::= story time now_plot`。
- 一条响应必须且只能包含一个正文根 `<content>`；其直接子节点必须且只能依次为一个 `<story>`、一个 `<time>` 和一个 `<now_plot>`，不得增加其他直接子节点。
- `<content>` 外不得出现任何文本或其他标签；唯一例外是零个或一个紧随 `</content>` 的尾随 `<UpdateVariable>`。
- `<story>` 与 `<time>` 都必须像上方示例一样写出显式起止标签，不得使用自闭合形式。
- `<content>` 不携带 `version="2"`，也不携带任何其他版本属性。
- `player` 属性可省略。`{#}` 仅在 `player` 元数据可用时解析为对应身份；没有可用元数据时保留为通用玩家气泡，绝不猜测玩家身份，且永不把 `#` 显示为姓名。
- 所有属性名区分大小写；不得重复属性，也不得用大小写变体夹带同义属性。
- `</content>` 外只允许一个可选的尾随 `<UpdateVariable>`。若出现，它必须恰好一个并位于输出末尾，其全部字节须原样保留，不得重排、格式化或改写。

## 标签模式

下表完整列出正文协议标签的属性与内容模型；除外部变量协议的 `<UpdateVariable>` 外，未列出的属性一律禁止。

| 标签 | 属性 | 文本与子节点 |
| --- | --- | --- |
| `<content>` | 可选 `player`；无其他属性 | 必须且只能按顺序包含一个 `<story>`、一个 `<time>`、一个 `<now_plot>`；不得有其他直接子节点。 |
| `<story>` | 必需 `volume`，值只能是 `01`–`39` | 内容为空且无子节点；必须写成显式起止标签。 |
| `<time>` | 必需 `period`、`layer`、`basis` | 必须有可见文本且无子节点，并沿用示例的魔女历显示风格（如 `魔女历1000年01月01日`）；`period` 使用词汇表的中文粗粒度时段，`layer` 使用项目的时间层词汇，`basis` 记录编辑或历史资料性质。必须写成显式起止标签。 |
| `<now_plot>` | 无属性 | 可包含自然旁白和结构化对白的直接文本，以及 `<scene>`、`<ability>`、`<check>`、`<restart>` 直接子节点；不得有其他子节点。 |
| `<scene>` | 必需 `location`、`time`、`mood` | 必须有文本内容；不得有子节点。 |
| `<ability>` | 必需 `user`、`name`、`kind`；可选 `affinity`；`kind` 必须恰为 `一般技能`、`权能`、`加护`、`魔法`、`精灵术`、`种族能力`、`武技` 之一 | 必须且只能按顺序包含一个 `<effect>` 和一个 `<description>`。 |
| `<effect>` | 无属性 | 必须有纯文本内容；不得有子节点。 |
| `<description>` | 无属性 | 必须有一至三句纯文本内容；不得有子节点。 |
| `<check>` | 必需 `type`、`actor`、`target` | 必须有文本内容；不得有子节点。 |
| `<restart>` | 必需 `deathId`、`checkpoint` | 必须有文本内容；不得有子节点。 |
| `<UpdateVariable>` | 属于外部变量协议，此处不定义其属性 | 只能作为尾随外部块出现零次或一次；其内部变量载荷不由本协议定义。 |

## 正文内容

- 自然旁白是 `<now_plot>` 内的直接文本。
- 结构化对白是独立成段的 `{人物}「对白」`。花括号位是唯一的说话者证据；全名或别名可以解析人物身份，但气泡显示人物短显示名。
- `scene`、`ability`、`check` 和 `restart` 只能是 `<now_plot>` 的直接子节点，且不得彼此嵌套；`ability` 按标签模式包含的一个 `effect` 和一个 `description` 是唯一例外。对白段也不得与这些特殊块彼此嵌套。
- `ability` 表示一次能力实际使用，`effect` 记录发动过程与实际结果；新生成必须包含一至三句 `description`。`affinity` 在未知或不适用时省略，否则只能是按 `火,水,风,土,阴,阳` 顺序排列、以半角逗号分隔的子集。

## 安全内容

- 安全行内格式只允许 `**strong**` 与 `*emphasis*`（分别呈现为粗体与强调）。
- 除协议规定的标签外，禁止原始 HTML、链接、图片、代码围栏及任何嵌套直接块。
- 格式错误或不受支持的片段保持惰性且可读；一个错误块不得抹掉合法的同级块，也不得据此补造事实。
