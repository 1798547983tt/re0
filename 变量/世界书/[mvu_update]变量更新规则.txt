变量更新规则:
  总则:
    - 变量只记录当前可变状态；原作资料、资料来源、置信度、角色知识、静态性格与背景由世界书负责，不写入变量。
    - 只根据本轮正文中已经发生且有明确因果依据的事实更新。不得为了显得活跃而随机改变数值、关系或事件。
    - 每次回复都检查所有顶层对象；没有变化的类别只在 Analysis 写 no change，不生成无意义 Patch。
    - 主角档案在初始化后锁定，聊天期间不得换成另一名角色。主角可以是任意原作人物或原创角色。
    - 菜月昴无论是否为主角，在当前世界中必须恰好保留一份动态状态：若他是主角，只存在于主角档案；若不是，则存在于关系.人物.菜月昴。
    - 数值仪表只表达叙事状态，不是原作官方属性，也不单独决定行动或战斗结果。

  Patch约定:
    - 只使用 add、replace、remove、move。
    - path 必须以 / 开头并严格对应中文变量路径。
    - add 用于新建对象、记录或数组项；新建 record 项时一次 add 完整对象。
    - replace 只用于已经存在的路径；不得对不存在的路径使用 replace。
    - remove 只用于确认存在且应清理的记录；move 只用于同一状态树内的关系迁移。
    - JSON Pointer 中的 ~ 编码为 ~0，/ 编码为 ~1。
    - 0~100 仪表必须写纯数字并保持范围；禁止附加百分号或单位。
    - 同一轮更新不得既回滚整个容器又继续从失败轮回写入该容器的子字段。

  初始化:
    - 当规则.初始化完成为 false 时，必须从用户开局信息一次性初始化所有已知状态；未知内容保留默认值，禁止猜测。
    - 初始化主角档案的姓名、角色类型、性别、年龄阶段、种族、身份、阵营、容貌、衣着、生存状态、状态仪表、能力与当前目标。
    - 初始化世界的规范日期、时段、时间层、轮回分支、地点、环境、危机等级、动向与势力态势。
    - 初始化关系、事件、线索和资产中与开局直接相关的条目，不加载全部人物资料。
    - 若主角不是菜月昴，必须在关系.人物中 add 完整的菜月昴动态状态；若主角是菜月昴，不得重复新增。
    - 初始化完成后把主角档案.主角锁定与规则.初始化完成改为 true，并把当时的世界、主角档案、关系、事件、线索、资产完整复制到第一份有效存档点状态快照；快照中的主角档案保持主角锁定为 true。

  世界:
    当前时间:
      - 规范日期使用项目魔女历；每年12月、每月30天。没有原作绝对日期时使用编辑演算或历史估算标记。
      - 时段只使用黎明、清晨、上午、正午、下午、傍晚、夜间、深夜、凌晨、时段未详，不擅自推算分钟。
      - 时间层只能是主线、轮回分支、历史回溯、试炼幻境。
      - 历史回溯和试炼幻境不推进主线世界时间；死亡回归后规范日期恢复到存档点，不累加菜月昴的主观经历时间。
    当前地点:
      - 按国家、地区、场所、具体位置分别记录；只在人物实际移动或场景明确切换后更新。
    环境:
      - 天气、光照或现场条件发生可感知变化时更新；描述保持简洁，只写会影响当前行动的环境状态。
    危机等级:
      - 只能是无、低、中、高、灾难；根据当前直接威胁更新，不因远方传闻自动提高。
    动向:
      - 最多保留3条与当前剧情有关的长期事件，每条含标题、阶段、类型、地点、描述。
      - 阶段只能按起→承→转→合推进。进入合并记录结果后，从动向移除；需要追踪结果时写入事件.近期记录。
    势力态势:
      - 只记录会影响当前剧情的势力，字段为立场、状态、描述；立场改变必须有事件依据。

  主角档案:
    - 主角锁定为 true 后，姓名与角色类型不得改变；化名只写入身份或当前形态，不更换主角。
    - 生存状态只能是存活、濒死、昏迷、失踪、生死未卜、死亡。
    - 生命、体力、魔力、精神稳定、门负荷、魔女余香均为0~100；仅在受伤、行动、施术、休息、治疗或明确精神冲击时更新。
    - 生命为0不自动等于死亡。只有正文明确确认实际死亡，才把生存状态写为死亡。
    - 伤势和异常状态使用稳定ID；获得时 add 完整对象，康复或解除时 remove 对应条目。
    - 战力等阶记录当前形态下的阶数、位阶、可战状态和生效条件；形态、场地、能力封锁或严重伤势变化时才更新。
    - 能力按加护、权能、魔法、精灵术、种族能力、武技、一般技能分类；每项记录状态、可用性、消耗或冷却、描述。
    - 当前目标只记录当前明确行动目标；目标完成、失败或放弃时更新或清空。

  菜月昴死亡与世界重启:
    - 只有当前运行世界中的菜月昴被正文明确确认实际死亡，才触发世界重启。
    - 濒死、昏迷、失踪、生死未卜、幻觉、替身死亡、试炼影像、历史回溯或未落地假设都不触发。
    - 一次死亡是一个事件。为该事件生成唯一死亡ID；同一ID无论被分段描述多少次，只能处理一次。
    - 每次触发必须在同一个 UpdateVariable 块中完成：
      1. add 一条完整的轮回.菜月昴死亡记录，记录重启编号、死亡时规范日期与时段、地点、直接原因、死亡经过与最后行动、相关人物、触发前轮回分支、本轮遗留情报。
      2. replace 轮回.世界重启次数为旧值+1，replace 轮回.当前轮回编号为旧值+1。
      3. replace 轮回.最近一次死亡与轮回.最近一次重启。
      4. 用状态快照分别 replace 世界、主角档案、关系、事件、线索、资产六个顶层容器；不得 replace 轮回根对象，死亡记录、重启次数、当前轮回编号、最近一次镜像与存档点本身不得被快照覆盖。
      5. 只给菜月昴保留本轮最多5条亲历遗留情报；其他角色默认不保留失败轮回记忆。
    - 若菜月昴不是主角，重启后必须恢复关系.人物.菜月昴的存活状态；若他是主角，则恢复主角档案的存活状态。
    - 世界重启不是多个事件；它是同一死亡事件的状态后果，但轮回次数和世界重启次数各增加一次。

  存档点:
    - 存档点只在叙事明确表明死亡回归锚点已经推进时更新，普通换场、睡眠、闲聊或模型判断不得推进。
    - 存档点记录有效、创建时间与世界、主角档案、关系、事件、线索、资产的完整状态快照；快照只包含当时的可变状态，不得复制世界书资料。
    - 更新存档点后，下一次世界重启以新存档点为准；旧存档点不再使用。

  关系:
    - 关系只保留伴侣、契约伙伴、人物三个容器；同一人物在三者中必须互斥。
    - 伴侣必须由叙事明确确认，不得把普通同伴或单向好感写成伴侣。
    - 契约伙伴用于精灵、契约对象和长期绑定伙伴，不使用宠物语义。
    - 人物只追踪近期登场、同行、失踪或会影响当前事件的人物，不加载完整人物档案。
    - 好感范围-100~100，信任和亲密度范围0~100；只有明确互动或重大事件才能改变，单次常规变化保持克制。
    - 关系迁移时先 add 目标容器完整对象，再 remove 原容器对象，并同步事件参与者等引用；不得同名双存。
    - 人物离场不等于立即删除。仅在长期无关且没有未完事件引用时清理；菜月昴永不因离场清理。

  事件与线索:
    - 进行中事件记录标题、类型、阶段、状态、地点、参与者、目标、描述；同一因果链使用同一事件ID。
    - 事件结束后从进行中移至近期记录。近期记录最多12条，超出时删除最旧且已结束的记录。
    - 当前线索最多30条，记录状态、关联事件、描述和下一步；未解决或正在使用的线索不得因裁剪删除。
    - 事件与线索随世界重启恢复到存档点；只有死亡记录中的本轮遗留情报跨轮回保留。

  当前战斗（短期状态）:
    - 战斗开始时 add 或 replace /事件/当前战斗，写入进行中 true、非空战斗ID、轮数、阶段“准备”、稳定ID字符串数组形式的参战者、先攻顺序、当前行动者与行动额度；距离、掩体、持续效果和濒死计数按参战者稳定ID记录。
    - 每次检定只 replace /事件/当前战斗/最近一次检定为可核对的结果摘要（检定类型、结果等级、总值、目标与时间）；不得写入骰池、随机种子、完整战斗日志或历史记录。
    - 战斗中的生命、体力、魔力、精神稳定和伤势仍回写对应的主角档案或关系 actor 长期字段；行动额度和临时效果只留在当前战斗。
    - 战斗结束时先将最终生命、资源与伤势回写长期 actor，再 replace /事件/当前战斗 为进行中 false、战斗ID ''、轮数 0、阶段 ''、参战者 []、先攻顺序 []、当前行动者 ''、行动额度 {}、距离 {}、掩体 {}、持续效果 {}、濒死计数 {}、最近一次检定 null。

  资产:
    - 货币、物品、装备和据点记录数量、持有者、存放位置、状态、损耗或当前效果。
    - 获得新资产时 add 完整对象；数量或状态变化时 replace 已有子字段；确认失去且数量为0时 remove。
    - 资产转移必须同时更新持有者与存放位置，不能在两个位置重复持有。
    - 资产随世界重启恢复到存档点，不保留失败轮回获得或消耗的结果。

  清理与不变量:
    - 近期事件最多12条，当前线索最多30条，单次死亡遗留情报最多5条。
    - 主角档案只有一个且不可切换；菜月昴动态状态恰好一份；关系容器同名互斥；死亡ID不可重复计数。
    - 动态 record 键使用稳定ID或规范姓名；显示名称变化不应破坏引用路径。
    - 不删除进行中事件、未解问题、有效存档点或跨轮回账本。
    - 持久化状态永远不保存骰池、完整战斗日志或检定历史；UpdateVariable 永远是每次回复的最后一个块。
