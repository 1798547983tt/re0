变量输出格式:
  rule:
    - 每次回复末尾输出且只输出一个 UpdateVariable 块；正文先完成，变量块置于最后。
    - Analysis 只写可核对的更新依据与 no change 结论，不输出资料考据、角色知识或隐藏推理。
    - JSONPatch 必须是合法 JSON 数组，只允许 add、replace、remove、move。
    - 每个 path 与 from 必须以 / 开头，严格对应中文变量路径，并遵守 JSON Pointer 转义。
    - 新增动态对象时先 add 完整对象；只有路径已存在时才能 replace；不得使用 delta 或 insert。
    - 没有状态变化时，JSONPatch 输出空数组 []，不得为了满足格式制造变化。
    - 所有数值保持 schema 规定范围并使用纯数字。
    - 首次初始化必须完整处理已知的主角档案、世界、轮回、关系、事件、线索、资产与规则状态；未知信息保留默认值。
    - 如果同一回合确认菜月昴实际死亡，死亡记录、两个计数器、最近一次镜像与存档点恢复必须在同一个 JSONPatch 数组中完成。

  format: |-
    <UpdateVariable>
    <Analysis>
    0.INITIALIZATION: ${是否需要初始化；主角档案是否已锁定；若已锁定不得切换。}
    1.TIME_LAYER: ${规范日期、时段、时间层、轮回分支是否改变。}
    2.LOCATION_ENVIRONMENT: ${国家、地区、场所、具体位置、天气、光照、环境是否改变。}
    3.CRISIS_WORLD: ${危机等级、世界动向、势力态势是否改变。}
    4.PROTAGONIST: ${生存状态、生命、体力、魔力、精神稳定、门负荷、魔女余香、伤势、异常状态、形态、战力等阶、能力、目标是否改变。}
    5.SUBARU_DEATH: ${是否明确确认当前世界中的菜月昴实际死亡；死亡ID是否已处理；非死亡情形必须明确排除。}
    6.RESTART_CHECKPOINT: ${世界重启次数、当前轮回编号、死亡记录、最近一次镜像、存档点是否改变；若重启，说明恢复范围。}
    7.RELATIONSHIPS: ${伴侣、契约伙伴、人物是否改变；检查同名互斥与菜月昴恰好一份。}
    8.EVENTS_CLUES: ${进行中事件、近期记录、当前线索、未解问题是否改变。}
    9.ASSETS: ${货币、物品、装备、据点是否获得、消耗、转移、损耗或回滚。}
    10.INVARIANTS: ${主角不可切换、死亡ID去重、历史上限、因果依据与 Patch 合法性检查。}
    11.COMBAT: ${战斗是否开始、结束或推进；战斗开始写入当前战斗的参战者、先攻顺序、阶段与行动额度；每次检定只写最近一次检定摘要，不写骰池或完整战斗日志。}
    </Analysis>
    <JSONPatch>
    ${只输出合法 JSON 数组；无变化时输出 []}
    </JSONPatch>
    </UpdateVariable>
