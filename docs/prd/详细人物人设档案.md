# 重写 153 份可直接扮演的 Re:Zero 详细人物人设档案

## Problem Statement

当前项目已有 153 份人物 TXT，但正文只有约 578–821 字符，且大量字段是跨人物复用的占位句，无法稳定支持角色扮演。现有“原文依据”主要来自剧情总结索引，尚未逐卷核验正传；若直接扩写，容易把总结、战力表或不同阶段误当成原作事实。

## Goal

重写现有 153 份档案，使每份正文目标为 2,000–3,000 个中文字符（核心人物可到 3,500），内容可直接驱动角色扮演。卷章证据继续可回查，但放在独立证据索引中，不把维护信息混入角色 TXT。

## Solution

建立“正传原文证据索引 → 规范姓名/别名 → 阶段与阶位 → 角色内容层渲染 → 机器校验”的流水线。每个 TXT 只写事实化的人物内容、阶段变化和可执行扮演规则；原文证据不足的角色仍保留，但用能力边界和保守行动表达未知。卷章命中、来源类型、置信度和审计说明留在独立索引中。生成器统一使用 UTF-8，顶层标签严格成对，战力参考只进入阶位与形态条件，不进入性格事实。

## Scope and source order

1. 正传第 01–39 卷原文是事实首要来源。
2. 剧情总结只用于导航和候选事件索引，不作为人物事实的唯一证据。
3. 战力参考只用于 T0–T6 到 1–7 阶的映射及相性说明；它明确是个人观点，不是性格或能力原文。
4. 不扩展外传、短篇、作者访谈、动画原创或联网资料。
5. 化名、译名、幼年/成年、失忆、尸人、借体和试炼状态合并在同一人物档案，实质变化写阶段。

## Profile contract

每个 TXT 保持单一顶层标签 `<姓名>...</姓名>`，并包含以下可执行段落：

- 身份与外在识别锚点
- 核心欲望、恐惧、底线与内在矛盾
- 价值观、日常状态、压力状态、战斗状态、亲密状态、被背叛状态
- 关键关系与触发反应
- 当前阶段的知识边界与秘密
- 权能、加护、魔法、技能、装备、触发条件、代价和限制
- 战斗决策、失败反应、让步条件与重新行动方式
- 说话方式、节奏、称呼、口吻禁区
- 3–5 条标注为“口吻示例”的短句，不冒充原文引语
- 阶段变化、切换条件、阶段专属战力等阶
- 互动决策、情绪变化、关系推进、危险禁区和优先级/代价

资料较少的档案仍保留，但只能扩写已知身份、能力边界、保守行为规则和可观察反应；不得伪造经历、关系、对白或能力。卷章依据、证据类型、资料置信度和存疑项由 `data/character_evidence.json` 等维护索引承载，不作为角色字段。

## User Stories

1. 作为 SillyTavern 使用者，我希望每个角色有独立 TXT 文件，以便按需导入而不混淆人物。
2. 作为角色扮演者，我希望看到欲望、恐惧、底线和内在矛盾，以便在没有固定剧情时做出一致反应。
3. 作为角色扮演者，我希望看到安全、压力、亲密、背叛和失败五类条件化反应，以便角色能随场景变化而不是只输出形容词。
4. 作为战斗场景作者，我希望看到能力触发条件、代价、限制和战斗决策顺序，以便避免无条件开大或跨阶段调用技能。
5. 作为长线剧情作者，我希望看到阶段切换条件和阶段专属阶位，以便区分幼年、失忆、封印、历史回溯和主线状态。
6. 作为项目维护者，我希望每条证据索引包含卷、章和近似行号，以便回到正传核查，而不是只能相信总结。
7. 作为项目维护者，我希望总结索引、正传原文和战力表在独立索引中被标成不同来源，以便识别推定和孤证，同时不污染角色 TXT。
8. 作为战力设定使用者，我希望严格采用 1–7 阶和上下位，并保留形态、场地、相性和启用条件，以便比较不被单一数字误导。
9. 作为低资料角色的使用者，我希望档案通过具体的未知边界和保守行动规则限制模型，不凭空编造关系、对白或能力。
10. 作为项目维护者，我希望批量生成可重复运行，以便新增原文、别名或手写内容后能重新渲染全部档案。
11. 作为项目维护者，我希望机器校验 UTF-8、标签、字段、篇幅、阶位和乱码，以便问题在导入 SillyTavern 前被发现。
12. 作为审阅者，我希望能从独立报告查看低置信度名单、篇幅分布和重复模板警告，以便优先人工复核高风险角色。

## Implementation seams

原文证据索引 → 规范姓名/译名映射 → 阶段与战力数据 → 详细档案渲染 → 静态校验与代表性扮演抽样。

## Implementation Decisions

- 事实入口只扫描本地正传第 01–39 卷；别名映射集中维护，短词匹配需要上下文过滤。
- 手写角色化内容与批量保守回退内容分离，回退内容不得覆盖已确认的人物事实。
- 每次生成先清理旧人物 TXT，再按规范姓名写入 UTF-8；维护 README 说明角色内容层与证据索引层的边界。
- 阶位采用 T0→7、T1→6、T2→5、T3→4、T4→3、T5→2、T6→1；形态写在同一角色文件的阶段段落。

## Testing Decisions

- 测试只断言外部契约：153 个文件、单一匹配标签、必需字段、2,000–3,500 字符、无乱码、合法阶位，以及不出现证据/审计字段。
- 证据测试确认代表角色存在正传记录，低证据条目标记 low，战力表不会伪装成正传来源。
- 校验器输出机器可读 JSON，供人工审阅和后续 CI 使用；重复模板只产生警告，不掩盖硬错误。

## Out of Scope

- 不纳入外传、短篇、动画原创、作者访谈或联网资料。
- 不把剧情总结或战力表孤证扩写为未核验的性格、关系、外貌和能力。
- 不在本次任务中制作 PNG/JSON SillyTavern 卡、修改 STDB 运行时或发布 Git 提交。

## Further Notes

低证据角色的 2,000 字目标通过“证据边界 + 条件化扮演规则”实现，而不是填充虚构传记。后续若补入新正传卷或人工核验，应先更新证据索引，再重新生成和校验。

## Acceptance

- 153 份人物档案全部存在且 UTF-8 可读。
- 每份正文达到角色类型对应篇幅目标，且无连续模板填充。
- 标签、字段、文件名、阶位和阶段结构通过机器校验。
- 证据索引保留卷号、章节标题和来源类型；角色 TXT 不嵌入这些审计字段。
- 资料较少条目不得凭空增加新事实，必须以未知边界和可执行限制表达。
- 抽查昴、艾米莉亚、雷姆、帕克、贝亚特丽丝、莱茵哈鲁特、罗兹瓦尔、艾姬多娜、雷古勒斯、艾尔莎、阿尔、奇夏、尤尔娜、普通人和低置信度条目，在安全、冲突、战斗、亲密、失败五类提示下保持阶段、知识和能力边界。
