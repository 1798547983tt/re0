## 本次渲染故障修复

旧产物的故障表现是静态壳层和主题按钮可见，但单个超大内联脚本在部分宿主代码块执行器中没有完成水合。新产物照《龙族》正式版改成“静态阅读壳层 + 末尾隐藏载体 + 分段脚本水合”：配置、人物、主题、协议、资产、渲染核心和启动入口拆成七个独立脚本段；入口只在挂载点内查找 app，并写入 `data-re0-script-seen`、`data-re0-runtime`、`data-re0-booted` 诊断状态。`runOnEdit=false`，已生成挂载点直接跳过；脚本异常时保留壳层并回退为不可执行文本。`<textarea>` 终止标签仍会被匹配器拒绝，避免载体逃逸。

本地独立酒馆运行时（SillyTavern 1.17.0、Tavern Helper 4.8.13）的同构 `srcdoc` 复测结果：七个脚本均加载，`data-re0-runtime=ready`，标题从测试协议解析为 `第01卷 | 开始的余温`，对白节点为 1，`aria-busy=false`。这不是用户目标实例的最终验收；目标实例仍需重新导入产物并按下方清单取证。

因此，已经导入旧 JSON 的 SillyTavern 会继续使用旧副本；请删除/覆盖旧的 `Re:0·正文美化` 后重新导入当前文件，再用新消息或重新绘制触发。不要只替换仓库文件名而不重新导入。

## 资产前置条件

当前清单中的 `releaseUrl` 全为空，且正则不内嵌约 9.65 MB 的图片。独立导入时，若 `./assets/...` 不在宿主可访问位置，Logo、背景和专属头像会安全降级；这不影响正文可读性，但不算视觉资产的生产验收。

如需在真实宿主显示完整图片，先获得发布授权，再把 `narrative/assets/` 中与清单哈希一致的 51 个图像发布到固定 commit/tag/release 的 HTTPS 地址，填写非空 `releaseRevision`，并让每个 HTTPS URL 明确包含该版本，再更新清单与打包测试后重新生成正则。解析器和审计器都会拒绝无版本或浮动 URL；不得在未授权时上传参考衍生素材。

## 真实 SillyTavern 验收顺序

1. 记录 SillyTavern、Tavern Helper、MVU、ZOD 与提示模板的精确版本，并核对 ZOD 脚本的既有 `name`、`id`、`export_with` 和固定 loader 未被宿主改写。
2. 导入正则，确认只匹配完整 `<content>...</content>`，`runOnEdit=false`；对已生成的消息编辑/重绘时不再重复包裹，且不会把 `<UpdateVariable>` 包进展示 HTML。
3. 发送一条严格协议的新消息，确认标题为 `第XX卷 | 标题`、日期为 `魔女历YYYY年MM月DD日`，左上角每条卡片各有一个 Logo。
4. 分别验证日间、夜间、自动时段切换和手动米色；刷新后检查主题偏好；键盘焦点应能到达四个至少 44px 的主题按钮。
5. 验证结构化对白的主角右侧/NPC 左侧、44 个安全别名专属头像、冲突别名通用回退，以及未知人物姓名首字头像。旁白中出现人名不得触发气泡。
6. 对同一消息执行编辑、swipe、重新生成与重绘，确认只有一个卡片；再切换聊天、返回历史和刷新，确认没有重复监听器或全局遮罩。
7. 渲染场景、能力、检定和世界重启块；检定必须显示骰面、逐项修正、总值、DC、等级和已结算后果。
8. 在每次生成前由可信调用方提供恰好 12 枚 1–20 的骰面；逐次检定从左到右消耗，不选骰、不补骰、不重掷；耗尽时应中止而不是编造结果。骰池与完整日志不得进入 `stat_data`。
9. 验证战斗开始写入 `事件.当前战斗`，回合推进更新最近一次检定，结束先回写生命/资源/伤势再清空短期字段；持久状态仍只有八个根。
10. 单独跑菜月昴明确实际死亡流程，确认唯一死亡 ID 去重、计数/镜像/存档恢复在同一更新批次完成；濒死、昏迷、失踪、替身、幻觉、历史回溯和试炼影像不得触发重启。
11. 断网、阻断资产 URL、禁用依赖各测一次；正文必须保持可读，首字头像与纯 CSS 背景生效，并明确报告依赖不可用。
12. 在约 320px、200% 缩放和系统“减少动态效果”下复验长标题、长人名、长对白、焦点与滚动；最后确认控制台无 error/warn。
